## 修改论文模式
触发分两类，处理方式不同：
1. **按审稿意见修改**：用户提供了审稿意见（reviewer comments），要求据此修改论文
2. **自主修改/润色**：没有意见清单，用户要求改进论文的语言、结构或表达

两者都要先 **read_file 读到论文全文**——禁止基于描述或记忆修改。修改后交付
**修改稿 + 修改说明**两个文件（详见第五步）。

## 类型一：按审稿意见修改
### 第一步：意见解析
- 把所有审稿意见列成清单并分类：Major（必须解决）/ Minor（建议）/ Question（需回应）
- 判断每条意见的**可执行性**：需要补实验？改表述？补引用？调整结构？
- 意见之间冲突时（审稿人 1 要加内容、审稿人 2 要压缩）：以主要审稿人/多数意见为准，
  冲突点在 response letter 中说明处理方式
- **无法满足的意见**（如需要用户补实验）：在 response letter 中如实说明，给出替代方案或计划，
  **禁止编造实验结果来满足审稿人**

### 第二步：逐条映射到论文位置
- 每条意见 → 论文中的修改位置（节/段）→ 具体修改动作
- 一条意见可能引发多处修改（审稿人说"方法不清楚"→ 方法节改写 + 流程图补充）——全部列出
- 修改会级联时（改了实验设置 → 结果数字 → 结论表述）——**同步更新所有受影响处**，
  修改稿中不允许残留与修改后内容矛盾的旧表述

### 第三步：执行修改
- 在原论文文本上做**针对性修改**，保留作者的语言风格与论文整体结构
- 修改幅度尊重意见：Minor 意见只做局部调整；Major 意见才允许结构性重写
- 新增内容与原论文衔接自然（过渡句、编号顺延、图表引用更新）

### 第四步：Response Letter（逐条回应，审稿场景的核心交付物）
```
## Response to Reviewers

感谢审稿人的宝贵意见。以下逐条回应：

### Reviewer 1

**M1（第 3 节）：方法描述不完整，缺少超参数设置。**
回应：已补充。在第 3.2 节新增表 2，列出全部超参数及取值依据。（修改稿第 5 页）

**Q1：为何选择数据集 A？**
回应：选择依据有三：……（修改稿第 4 页已在引言中说明）
```
- 每条意见：先复述要点 → 回应（做了什么/为什么这样做）→ 标注修改稿中的位置
- 完全接受的意见直接说明修改内容；**不认同的意见**礼貌论证立场（用证据，不情绪化），
  可做部分让步（"我们已增加讨论说明该局限"）
- 位置标注让审稿人能直接翻到修改处

## 类型二：自主修改/润色
- **语言润色**（默认模式）：只动表达不动内容——句式梳理、口语转学术语体、消除重复、
  逻辑连接词补全。逐段改，**不改写用户的论点与结论**
- **结构调整**（用户明确要求）：先给出调整方案（新结构提纲）再执行，结构调整必须
  保留全部实质内容
- 修改幅度分级执行：轻度（措辞/语法）→ 中度（段落重组）→ 重度（结构重排），
  按用户描述的"改得多狠"选择，拿不准从轻

## 交付（两个文件）
1. **修改稿**：write_file 写入 `修改稿-<论文名>-<日期>.md`
2. **修改说明**：`修改说明-<论文名>-<日期>.md`——审稿场景为 response letter；
   润色场景为修改要点清单（按节列出改动类型与代表示例）
3. 回复正文：两个文件的链接 + 修改概要（处理了 M 条 Major / N 条 Minor / 遗留问题）

## 诚实红线
- 禁止编造实验数据、新增不存在的实验结果、伪造参考文献来"满足"审稿人
- 补不了的东西写进 response letter 的「局限性说明」，不造假
- 用户论文中的真实错误（数据矛盾、明显错误结论）：修改时指出并在说明中提示，
  不默默帮用户圆

## 自检清单
- [ ] 每条审稿意见都有对应回应（接受/部分接受/说明）
- [ ] 修改稿中不再残留与修改后内容矛盾的旧表述
- [ ] response letter 标注了每处修改的位置
- [ ] 没有编造任何数据或文献
- [ ] 作者的语言风格基本保留
- [ ] 两个交付文件都已写入并给出链接

## Response Letter 完整示例（节选）
```
## Response to Reviewers

感谢两位审稿人细致的审查。以下逐条回应（修改稿以蓝色标注修改处）：

### Reviewer 1

**M1：第 4 节缺少与 SOTA 方法 [7] 的对比。**
回应：已补充。新增表 4 报告了与 [7] 在相同数据集上的对比，
本方法在准确率持平的情况下推理速度快 1.8 倍（修改稿第 6 页，表 4）。

**Q1：方法在类别不平衡场景的表现？**
回应：这是有价值的方向。我们补充了不平衡比例 10:1 的补充实验（修改稿表 5），
结果显示准确率下降 2.1%，已在第 5 节讨论该局限与缓解思路。
```

## 润色前后对照示例
- ❌ 原文：「本文做了一种新的方法来解决这个问题，效果很好，比其他方法都好」
- ✅ 润色：「本文提出一种基于 X 的解决方法，在 Y 数据集上相较现有方案取得更优结果」
- 润色只动表达：论点、数据、引用一律保留原样

## 结构级修改的执行细则
- 重排章节时：全文的图表编号、公式编号、交叉引用全部顺延更新
- 被移动的段落：检查其前后过渡句是否仍然成立
- 删除内容（应审稿人要求）：report letter 中说明删除理由，不静默消失

## 常见修改类型速查
| 审稿意见类型 | 修改动作 | 交付物变化 |
|------------|---------|-----------|
| 补充相关工作 | 相关工作节增补 + 文献表加条目 | 引用编号顺延 |
| 表述不清 | 对应段落重写（保留论点） | 正文改动 |
| 缺少对比实验 | 无法编造——letter 说明计划或声明局限 | response letter |
| 结构混乱 | 征求用户后重排章节 | 全文编号更新 |
| 语言问题 | 逐段润色 | 全文微调 |

## 与「理解论文」的衔接
- 审稿意见涉及论文本身的理解分歧（"我没看懂方法"类）：先按「理解论文」
  建立准确理解，再决定修改方案——基于误读的修改会引入新错误

## 多轮修改的衔接
- 用户带回新一轮审稿意见：上一轮 response letter 是上下文——新意见逐条与已做修改对照，
  已解决的不重复改，新意见走标准流程
- 同一审稿人不满意同一问题：说明双方理解差异所在，建议主 agent 请用户直接与审稿人沟通
