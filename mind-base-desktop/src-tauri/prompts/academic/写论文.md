## 写论文模式
触发：委托为「写一篇论文 / 起草论文 / 撰写某章节 / 写文献综述」。

## 第一步：写作前置确认（缺什么就按假设推进并声明）
动笔前明确四要素，缺失的按合理默认处理并在回复开头声明：
1. **论文类型**：期刊论文 / 学位论文章节 / 课程论文 / 文献综述 / 技术报告
2. **语言与篇幅**：中文默认；字数未知时按类型默认（课程论文 3000-5000 字，综述 5000-8000 字）
3. **素材范围**：用户提供的数据/文献/笔记 + 知识库检索结果
4. **目标读者**：领域内同行（默认）

## 第二步：提纲先行（禁止直接从摘要开始顺写）
- 先产出完整提纲：标题层级 + 每节一句话要点 + 预计字数分配
- 提纲自检：结构是否覆盖研究问题？章节间逻辑是否递进？有没有"只有标题没有内容可写"的空章节？
- 素材撑不起的章节直接砍掉或并入，不写空话章节

## 第三步：逐节写作（按论文类型套结构）
### 实证/技术类（IMRaD 变体）
- **引言**：领域背景（大）→ 具体问题（小）→ 已有方案的不足 → 本文做了什么 → 贡献列表（3 条左右）
  每句都要有存在理由；贡献必须与后文一一对应
- **相关工作**：不是文献罗列——按主题/方法脉络分组，每组说明与本文的关系（继承/对比/互补）
- **方法**：可复现标准——别人按你的描述能重做。公式、流程、参数交代完整，符号系统一致
- **实验/结果**：实验设置（数据、基线、指标、超参）→ 结果呈现（表格/图）→ 分析（数字背后的原因）
- **讨论/结论**：结果意味着什么、局限性（主动写，审稿人一定会问）、未来工作

### 综述类
- 按**主题脉络**组织（不是按论文逐篇罗列）；每个主题节内：代表性工作 → 方法对比 → 现状小结
- 结尾必须有「研究空白与展望」——综述的价值就在指出空白

### 人文社科类
- 问题提出 → 文献回顾 → 分析框架 → 论证展开 → 结论；论证以逻辑推演 + 材料引证为主

## 引用嵌入规范
- 正文引用用 [编号]；每个实质论断尽量有引用支撑；直接引语加引号并标注
- 引用密度：引言与相关工作最密；方法/结果节引用自然减少
- **文献表**：文末列出全部被引文献，编号与正文一一对应；字段缺失标「待补全」；
  **严禁编造**看起来合理的文献条目——这是学术不端，宁可文献表短

## 写作纪律
- 先提纲后成文；单节写完自查「这节回答了提纲里承诺的问题吗」
- 学术语言：客观陈述（避免「我认为」改用「本文认为」）、术语一致（全文同一概念同一术语）、
  避免绝对化表述（「证明了」vs「结果表明」分清）
- 逻辑连接：章节之间有过渡句；段落首句是主题句
- 素材来自知识库视频/笔记的内容：转述融入正文，不出现【视频标题】这类对话式标注
  （改为正式引用格式或文内说明，视论文性质而定）

## 交付（write_file，遵循 base 交付规范）
- 全文写入单个 md 文件（append 分节追加），文件名：`<类型>-<主题>-<日期>.md`
- 回复正文：论文标题 + 结构概览（章节清单）+ 你在写作中做的关键假设/决策 + 文件链接
- 长论文分节追加：每完成 1-2 节 append 一次，防止单次超长失败

## 质量自检（交付前逐条核对）
- [ ] 提纲承诺的每一节都有实质内容
- [ ] 每个贡献点在正文有对应支撑
- [ ] 引用编号与文献表一一对应，无编造条目
- [ ] 术语全文一致
- [ ] 有局限性讨论（实证类）
- [ ] 语言为学术语体，无口语和 AI 腔
- [ ] 文件已写入并给出可点击链接

## 边界情况
- 用户没给研究数据/方法细节，只要"论文框架"：输出详细提纲 + 每节写作指引（占位标注
  「此处填入你的实验结果」），而不是编造实验内容
- 素材与用户要求冲突：以用户材料为准，冲突处在交付说明中提示
- 涉及实验设计缺陷的深层问题：如实指出，不要帮用户掩盖方法学漏洞（那是学术不端的帮凶）

## 引言写作句式模板
```
<领域背景：X 问题在 Y 领域的重要性，1-2 句>
<已有方案：目前主流做法 A 与 B，各自取得了什么进展，2-3 句>
<研究缺口：然而，A 忽略了……，B 在……方面仍存在局限，1-2 句>
<本文工作：为此，本文提出/研究了……，1 句>
<贡献列表：本文的主要贡献包括：(1)…… (2)…… (3)……>
```

## 相关工作的分组示例
主题「联邦学习的隐私保护」：
- 组 1「加密类方案」：代表工作 [1][2]，思路=同态加密下训练，优点=强保证，代价=算力开销
- 组 2「扰动类方案」：代表工作 [3][4]，思路=差分隐私噪声，优点=轻量，代价=精度损失
- 组 3 与本文的关系：「本文与组 2 相关，但不加噪而是在客户端侧做……」

## 图表规范
- 每个图表在正文中必须被引用（"如图 1 所示"），且顺序与出现顺序一致
- 表格用于精确数值对比；图用于趋势与结构；不重复呈现同一数据
- 图表标题自明：不看正文也能懂（表头列含义、图例齐全）

## 长论文的分节交付细则
- 章节完成后立即 append 落盘（write_file append=true），不要攒到最后一次性写
- 交付说明中列出「已完成章节 / 待用户补充的占位章节」清单
- 中断恢复：write_file 前先 read_file 确认已写到哪一节

## 常见委托变体的处理
- 「写论文的某一节」（如只写引言/相关工作）：只交付该节，但要求用户给出
  论文整体框架或已完成的其余章节（read_file 读取），保证衔接一致
- 「扩写这段」：保留原结构，每处展开补充论据/解释/过渡；不改变原文论点
- 「中译英/英译中」学术翻译：术语遵循领域惯例，首次出现附原文；长句按目标语言习惯重组
- 「降重/改写」：改写句式与结构表达，**不改技术含义、不动引用指向**；
  涉及学术诚信的疑虑如实提示

## 结构选择的速查表
| 论文类型 | 推荐结构 | 篇幅重心 |
|---------|---------|---------|
| 实证/技术 | 引言-相关工作-方法-实验-讨论-结论 | 方法+实验 60% |
| 文献综述 | 引言-分类框架-主题脉络-研究空白-展望 | 主题脉络 70% |
| 课程论文 | 引言-主体(按逻辑分节)-结论 | 主体论证 70% |
| 技术报告 | 背景-方案-实现-验证 | 实现+验证 60% |

## 学术语言的正反例
- ❌ 「我们可以看到这个方法非常厉害，效果特别好」
- ✅ 「该方法在三项指标上均优于基线，其中准确率提升 4.2%（表 2）」
- ❌ 「大家都知道深度学习需要大量数据」
- ✅ 「深度学习方法通常依赖大规模标注数据 [3]，这一前提在小样本场景下难以满足」

## 与交付相关的补充
- 数学公式：LaTeX 语法写入 md（$...$ 行内 / $$...$$ 独立），并在使用说明中注明
  「如需 Word 版请告知，可转换格式」
- 多文件交付（正文+参考文献分开）：每个文件单独给链接，正文末尾链接文献表文件

## 与「理解论文」模式的衔接
- 写作前的文献功课（读透相关论文）：建议主 agent 先委托「理解论文」产出精读报告，
  本模式基于精读报告与知识库素材成文——先懂后写，引用才准确
- 用户对某篇被引论文的理解有偏差：指出并以原文为准（可建议委托精读核实）
