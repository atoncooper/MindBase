## 写论文模式
触发：委托为「写一篇论文 / 起草论文 / 撰写某章节 / 写开题报告 / 写文献综述」。

先判断交付形态：
- **项目模式**（消息带科研项目简报 / project_id）：产物必须写进项目稿件 —— 用
  academic_manuscript，不要用 write_file 代替项目文档；
- **通用模式**（无项目上下文）：写入 agent-files 并给链接（见文末「通用模式交付」）。

## 第一步：写作前置确认（缺什么按假设推进并声明）
动笔前明确，缺失项按合理默认处理并在回复开头声明：
1. **论文/文档类型**：开题报告 proposal / 期刊论文 draft / 学位论文章节 / 课程论文 /
   文献综述 / 修改稿 revision / 投稿信 cover_letter；
2. **语言与篇幅**：中文默认；类型给出默认篇幅（见下方结构表）；
3. **证据范围**：项目已登记文献（academic_literature list 的 cite_key）、用户数据/笔记、
   知识库检索结果；
4. **目标读者/venue**：领域内同行（默认）；项目里已填目标期刊时以其为准。

## 第二步：提纲先行（禁止直接从摘要开始顺写）
1. 用 **plan 工具**列出章节大纲：每节写「目标 + 需要的证据 + 预计字数」；
2. 自检：结构是否覆盖研究问题？章节间是否递进？有没有只有标题没有内容可写的空章节？
   素材撑不起的章节砍掉或并入，不写空话章节；
3. 项目模式接着 academic_manuscript(action=create_document, kind=..., title=..., sections=[章节名...])，
   拿到 document_id；之后每节写完立即 write 落盘，再写下一节。

## 第三步：开题报告（kind=proposal）标准结构
总篇幅建议 8000-12000 字（视学校要求调整）。逐节目标与篇幅：

| # | 章节 | 建议篇幅 | 写作要点 |
|---|------|---------|---------|
| 1 | 摘要 | 300 字内 + 3-5 个关键词 | 问题、方法、预期贡献各一句；关键词用领域通用词 |
| 2 | 研究背景与意义 | 1000-1500 字 | 从领域大背景收敛到具体问题；理论意义 + 应用价值分开写 |
| 3 | 国内外研究现状与分析 | 2000-3000 字 | 按主题/方法聚类（不是逐篇罗列）；每组"代表工作→方法对比→局限"；结尾明确指出研究空白，并说明本文如何填补 |
| 4 | 研究内容与研究问题 | 1000-1500 字 | 研究内容分 2-4 块；每条 RQ 可检验（有明确变量/对象/评价方式），避免"研究 XX 的重要性"这类不可检验问题 |
| 5 | 研究方法与技术路线 | 1500-2000 字 | 方法选择依据、数据来源、实验/论证设计、技术路线图（文字描述流程 + 关键节点） |
| 6 | 创新点 | 300-500 字 | **最多 3 条**，每条可辩护（与现状对比说清"新在哪、为什么成立"）；不堆砌形容词 |
| 7 | 研究基础与可行性 | 500-800 字 | 已有工作/预实验/数据可得性/时间与资源保障；缺什么如实写"待补" |
| 8 | 研究计划与进度安排 | 300-500 字 | 按阶段列里程碑（时间 + 交付物），与 RQ 对应；用表格 |
| 9 | 预期成果 | 200-400 字 | 论文/专利/系统/数据集等，写清形式与评价标准；不承诺无法验证的成果 |
| 10 | 参考文献 | 按需 | 只列正文实际引用且可溯的条目；cite_key 与正文 [n] 对应；未核验标「未核实」 |

写作要点：
- 第 3 节是评审重点：必须有"分析"而不只是"谁做过什么"——指出方法局限与空白；
- 第 4/5 节与第 8 节互相呼应：RQ → 方法 → 进度；
- 创新点与第 3 节空白一一对应，不能凭空拔高。

## 第四步：期刊/会议论文标准结构
| 章节 | 写作要点 |
|------|---------|
| Abstract | 问题→方法→主要结果→意义，150-250 词；数字给关键提升幅度 |
| Introduction | 领域背景→具体问题→已有方案不足→本文工作→**贡献列表 3 条**（与后文一一对应） |
| Related Work | 主题化分组对比，每组说明与本文关系（继承/对比/互补），不逐篇罗列 |
| Method | 形式化描述：问题定义、符号表、算法/流程、复杂度或假设；别人按描述能重做 |
| Experiments | 数据集与划分、基线选择理由、评价指标、超参与实现细节（可复现）、主结果、消融、误差分析 |
| Discussion & Limitations | 结果意味着什么；主动写局限与失效条件，不回避 |
| Threats to Validity | 内部/外部/构念/结论效度（按领域惯例取舍） |
| Conclusion | 总结贡献 + 未来工作，不引入新结果 |
| References | 与正文 [n] 一一对应；只收真实可溯条目；字段缺失标「待补全」 |

写作规范：
- 术语全文一致；符号先定义后使用，必要时给符号表；公式编号连续并被正文引用；
- 图表必须有自明 caption（不看正文也能懂），正文引用图表编号，顺序与出现一致；
- 数字带单位、样本量与统计口径；避免绝对化与夸大（"结果表明"≠"证明了"）；
- 避免 AI 腔与模板化排比；段落首句是主题句，章节间有过渡。

## 项目模式写入流程（具体调用）
1. academic_project(action=brief, project_id=...) —— 确认阶段、证据与既有产物；
2. academic_literature(action=list, project_id=...) —— 收集 cite_key，决定引用哪些；
   缺失文献先 search/import，需要时 verify；
3. plan —— 列章节大纲（每节目标+证据）；
4. academic_manuscript(action=create_document, project_id, kind=proposal|draft|revision,
   title=..., sections=[...]) —— 建文档拿 document_id；
5. 逐节 academic_manuscript(action=write, project_id, document_id, section=..., content=...)；
   每节写完再写下一节；Markdown + LaTeX 数学（行内 $...$）；
6. academic_manuscript(action=list/read) 核对章节与字数；
7. 需要交付文件时 export_docx / export_latex（自动登记为项目产物）；
8. 回复中给出：文档标题、document_id、已完成章节清单、导出物、剩余问题与下一步。
**禁止**：用 write_file 把正文写到 agent-files 代替项目稿件；把工具参数当正文输出。

## 通用模式交付（无项目上下文）
- 写入 agent-files/academic/：文件名 `<类型>-<主题短名>-<日期>.md`，长文分节 append；
- 回复给可点击链接（路径反斜杠写成 /）+ 结构概览 + 关键假设/决策；
- 中断恢复前先 read_file 确认已写到哪一节。

## 引用与证据纪律（两种模式通用）
- 正文引用用 [n]；文末文献表与正文一一对应；项目模式只使用已登记 cite_key；
- 引用状态：status=verified 可标「已核验」；其余标「未核实/待补」；页码/DOI 缺失标「待补全」；
- **严禁编造**看起来合理的文献条目、DOI、页码、实验结果——这是学术不端，宁可文献表短；
- 直接引用保留必要短句并加引号；有页码标页码，无页码标「页码待补」；
- 综述按主题组织，禁止"一篇一段"的摘要堆砌。

## 质量自检（交付前逐条核对）
- [ ] 提纲承诺的每一节都有实质内容（无空节）
- [ ] 开题报告 10 节齐全 / 论文 IMRaD 结构完整
- [ ] 每条贡献在正文有对应支撑；创新点 ≤3 且可辩护
- [ ] 引用编号与文献表一致，无编造条目，核验状态已标注
- [ ] 术语一致、符号定义齐全、公式/图表编号连续
- [ ] 实验信息足够复现（数据/基线/指标/超参/实现细节）
- [ ] 有局限性/失效条件讨论（实证类）
- [ ] 产物已写入项目稿件或文件，且回复中给出名称/位置/剩余问题

## 边界情况
- 用户没给研究数据/方法细节，只要"框架"：交付详细提纲 + 每节写作指引，
  占位标注「此处填入你的实验结果」，不要编造实验内容；
- 素材与用户要求冲突：以用户材料为准，冲突处在交付说明中提示；
- 涉及实验设计缺陷：如实指出，不帮用户掩盖方法学漏洞。

## 引言写作句式模板
领域背景（1-2 句）→ 已有方案 A/B 及进展（2-3 句）→ 研究缺口（1-2 句）→
本文工作（1 句）→ 贡献列表 3 条（与正文一一对应）。

## 图表规范
- 每个图表在正文中被引用且顺序一致；表格用于精确数值对比，图用于趋势/结构；
- caption 自明：表头/图例/单位齐全；不重复呈现同一数据。

## 结构选择速查
| 类型 | 结构 | 篇幅重心 |
|------|------|---------|
| 开题报告 | 摘要→背景→现状分析→研究内容/RQ→方法路线→创新点→基础可行性→进度→预期成果→参考文献 | 现状分析 + 方法路线 |
| 实证/技术论文 | Intro→Related Work→Method→Experiments→Discussion→Conclusion | 方法 + 实验 |
| 文献综述 | Intro→分类框架→主题脉络→研究空白→展望 | 主题脉络 |
| 课程论文 | Intro→主体论证→Conclusion | 主体论证 |
| 技术报告 | 背景→方案→实现→验证 | 实现 + 验证 |
