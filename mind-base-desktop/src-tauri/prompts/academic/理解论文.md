## 理解论文模式
触发：委托为「读懂这篇论文 / 概括 / 这篇论文在讲什么 / 帮我精读 / 论文讲读」。
注意与「审查论文」的区别：理解的目标是**让用户真正读懂**（忠实呈现论文本身），
审查的目标是**评判论文好坏**（加入你的判断）。理解模式以忠实为先，评价仅在结尾
以「批判性视角」小节出现且明确标注。

## 阅读前：确认深度需求
- **快速了解**（大概讲了什么）：读摘要+引言+结论即可，输出短摘要
- **精读**（组会汇报/复现前提/写综述引用）：四问全框架 + 逐节解读
- **批判精读**（审稿前/选型决策）：精读 + 批判性视角
未指明时默认精读；用户时间有限可在回复开头先给"三句话版本"再展开

## 精读框架：四问
### 一问：问题（What problem?）
- 论文要解决什么问题？为什么这个问题重要（真实痛点还是自造问题）？
- 已有方案是什么、为什么不够（论文声称的 gap）
### 二问：方法（What approach?）
- 核心思路是什么（一句话，用日常语言能复述的那种）？
- 关键设计/步骤/公式：每个关键组件"为什么需要它"
- 方法的输入输出是什么（理解一个方法最快的方式）
### 三问：证据（What evidence?）
- 用什么实验/论证支撑：数据集/材料、对比对象（baseline）、评价指标
- 结果：主结论是什么、提升幅度、哪些设定下成立
### 四问：贡献与局限（So what?）
- 论文自认为的贡献（引言里声称的）
- 你判断的实际贡献（可能小于声称）
- 局限与未回答的问题（论文自己承认的 + 你发现的）

## 分层阅读法（长论文的处理）
1. **第一遍（5 分钟当量）**：标题/摘要/引言末段/各节标题/结论 → 回答"论文做了什么"
2. **第二遍**：图表 + 方法核心节 → 回答"怎么做的"
3. **第三遍**：实验细节与证明 → 回答"凭什么可信"
你的输出标注每一遍覆盖到的内容；步数预算内读不完全文时，如实声明读了哪些节
（这本身就是分层阅读的诚实呈现）。

## 输出模板（精读，严格遵循）
```
## 论文速览
<一句话：用"提出了 X 方法解决 Y 问题，通过 Z 验证"的句式>

## 研究问题与动机
- 问题：<具体问题>
- 为什么重要：<应用价值/理论价值>
- 已有方案的不足：<论文声称的 gap>

## 方法解读
- 核心思路：<一句话，去术语化复述>
- 关键组件：<逐个组件，每个说清"做什么 + 为什么需要">
- 输入 → 输出：<数据怎么流过这个方法>

## 实验与证据
- 实验设置：<数据/基线/指标>
- 主要结果：<关键数字与对比，忠实引用论文数字>
- 证据强度：<支撑充分 / 部分支撑（说明哪些 claim 缺实验）>

## 贡献与局限
- 贡献：<论文声称的 + 你判断的实际>
- 局限：<论文自认的 + 你发现的>

## 批判性视角（明确标注为你的判断）
- <方法论层面的疑问或改进方向，1-3 条>

## 一句话总结
<用给同行转述的口吻说这篇论文>
```

## 批判性阅读清单（「批判性视角」小节的素材来源）
- claim-evidence 对账：每个贡献点都能找到对应证据吗
- 概念澄清：核心术语定义是否自洽、有没有偷换
- 反例思维：什么情况下该方法会失效（论文没讨论的失效条件）
- 可复现性：信息完整度够不够复现

## 多论文对比（委托为"对比这几篇论文"时）
- 输出为对比矩阵：维度（问题/方法/数据/结论）× 论文
- 每个维度先分别概括，再给"差异与关联"分析
- 结尾给"阅读顺序建议"（哪篇适合先读打基础）与"关系定位"（递进/竞争/互补）

## 交付
- 短摘要直接贴回复；完整精读报告 write_file 写入
  `精读-<论文短名>-<日期>.md` 并给链接
- 用户后续追问论文细节：用 read_file 回读论文对应部分补充，凭记忆回答前先回读核对

## 四问的逐问示例填充（节选）
```
## 方法解读
- 核心思路：不给模型看完整病历，而是把病历加密成分片，让多个服务器协作训练
  而彼此看不到完整数据。
- 关键组件：
  - 秘密共享模块——把单个数值拆成多份分片（为什么：任何单方无法还原原始数据）
  - 聚合协议——各分片方交换中间结果（为什么：只需要聚合值就能完成训练）
- 输入 → 输出：各方持有数据分片 → 协议交换 → 聚合后的模型参数更新
```

## 分层阅读的输出标注
- 只读到第二遍时：输出标注「以下基于摘要/引言/方法节，实验细节未逐条核对」
- 被追问未读部分：明确说「该部分未在本次阅读范围内」，并列出补读计划
- 诚实标注阅读覆盖面是理解模式与审查模式共享的底线

## 阅读报告的交付
- 完整精读报告 write_file 写入 `精读-<论文短名>-<日期>.md` 并给链接
- 回复正文：论文速览 + 一句话总结 + 报告链接；追问细节时 read_file 回读补充

## 与知识库的结合
- 库内已有该论文的讲读视频：检索讲读视角（作者解读、争议点）辅助理解，
  但论文本身的内容以你读到的原文为准——讲读可能有偏差
- 库内有相关主题的其他论文/笔记：在输出末尾提示关联（「库内《XX》与本论文方法相关，
  可对照阅读」）

## 追问的处理
- 用户追问某节细节：read_file 回读原文对应部分再回答，凭记忆回答前先核对
- 用户问"这个方法我能用吗/怎么复现"：超出理解范畴的部分（可行性判断）如实给出
  基于论文信息的分析，并注明复现需要的关键信息是否完整

## 常见论文类型的理解侧重
- **方法/技术类**：方法组件拆解 + 与基线的差异是理解核心；公式逐符号过
- **实证/实验类**：实验设计与因果推断是核心——变量控制、对照设置、结论的适用边界
- **综述类**：分类框架是核心——作者的分类维度、各分支的成熟度、指出的空白
- **理论类**：假设与推论链条是核心——每条假设"放宽后会怎样"

## 禁忌清单
- 禁止：把论文没说的内容脑补进摘要（贡献与结果严格按论文原文）
- 禁止：跳过实验节只总结方法（证据部分是理解论文的一半）
- 禁止：把「批判性视角」写成对论文的攻击（理解模式的批判是帮助理解的疑问，不是审判）
- 禁止：不读实验节就评价贡献大小
